# 00 · 总览：一条从模板到 DOM 的完整链路

> 本项目是跟着《Vue.js 设计与实现》手写的最小可用 Vue 3。
> 零依赖、纯 ESM。所有代码都可以直接读，每个文件头部都写了"为什么这么设计"。

## 一、先回答最大的问题：模板是怎么变成 DOM 的？

你在组件里写：

```html
<button @click="count++">点了 {{ count }} 次</button>
```

浏览器并不认识这段"HTML + 表达式"的混合体。它变成真实 DOM 要经过 **五步**：

```
① tokenize     字符串 → token 流        ["<button @click=..>", "点了 ", "{{ count }}", " 次", "</button>"]
② parse        token 流 → 模板 AST      树形结构，属性被分成"静态"和"指令"两类
③ transform    模板 AST → JS AST        语义转换 + 优化标注（patchFlag / 静态提升 / 块）
④ generate     JS AST → 代码字符串      一段真的能跑的 JS 源码
⑤ new Function 代码字符串 → render 函数  从此"模板"这个概念消失了
```

得到的 render 函数长这样（去试试 `examples/compile-pipeline.html`，可以实时看到）：

```js
function render(_ctx, _cache) {
  return (_openBlock(), _createElementBlock("button", {
    onClick: $event => (_ctx.count++),
  }, "点了 " + _toDisplayString(_ctx.count) + " 次", 1 /* TEXT */))
}
```

之后每次组件渲染，就执行这个函数拿到一棵 **VNode（虚拟节点）树**，渲染器把它和
上一次的树做对比（diff），只把**真正变化的部分**落到真实 DOM 上。

## 二、数据变化时发生了什么？

```
state.count++
  → Proxy 的 set 拦截（reactivity/reactive.js）
  → trigger：翻"账本"找到所有读过 count 的 effect（reactivity/dep.js）
  → 组件的渲染 effect 在账本里 → 调用它的 scheduler（不立刻执行！）
  → queueJob：渲染任务进队列（reactivity/scheduler.js）
  → 微任务 flushJobs：本轮所有数据修改合并，每个组件只重渲染一次
  → effect.run() → render() 重新执行 → 新 VNode 树
  → patch(旧树, 新树)（runtime-core/renderer.js）→ 最小化 DOM 操作
```

## 三、目录结构

```
src/
├── shared/              位标记与工具
│   ├── shapeFlags.js      VNode 类型的位掩码（元素/组件/文本/片段 + children 形态）
│   ├── patchFlags.js      编译器给运行时的"更新提示"（哪个属性会变）
│   ├── normalizeProp.js   class/style 三种写法的归一化
│   └── utils.js
├── reactivity/          响应式系统
│   ├── dep.js             账本：track / trigger
│   ├── effect.js          ReactiveEffect：可重新执行的函数 + 依赖清理
│   ├── reactive.js        Proxy 拦截（含数组方法仪表化）
│   ├── ref.js             原始值的响应式 + proxyRefs（模板不用写 .value）
│   ├── computed.js        缓存 + 惰性
│   └── scheduler.js       批量更新队列 + nextTick
├── runtime-core/        平台无关的运行时
│   ├── vnode.js           VNode 结构 + Block Tree（动态后代收集）
│   ├── renderer.js        mount / patch / 双端 diff / 卸载
│   ├── component.js       组件实例、setup、props、emit、渲染 effect、provide/inject
│   ├── h.js               h()、withCtx、renderSlot（插槽）
│   ├── lifecycle.js       生命周期钩子注册
│   ├── instance.js        "当前组件实例"上下文（打破循环依赖的最小模块）
│   └── runtimeHelpers.js  编译产物调用的 _xxx 函数（编译器↔运行时的契约）
├── runtime-dom/         浏览器适配层
│   ├── nodeOps.js         增删改查真实 DOM 的 9 个函数
│   ├── patchProp.js       属性/事件/class/style 落到 DOM 的所有细节
│   └── index.js           createApp（组装 nodeOps + 渲染器）
├── compiler-core/       编译器
│   ├── tokenize.js        有限状态机（词法分析）
│   ├── ast.js             模板 AST 节点定义
│   ├── parse.js           栈式解析（语法分析）
│   ├── expression.js      标识符加 _ctx. 前缀（prefixIdentifiers）
│   ├── transform.js       v-if/v-for/v-model 转换 + patchFlag + 静态提升 + 块
│   ├── js-ast.js          JS AST 构造器 + 打印器
│   ├── codegen.js         AST → 源码字符串
│   └── index.js           compile() 把五步串起来
└── index.js              对外出口：把编译器注入运行时（"完整版 Vue"的关键一步）
```

## 五、和真实 Vue 的差距（诚实清单）

本实现覆盖了主干的 90%，省掉了工程化的 90%。差距主要在：

- 无 SSR / hydration、Teleport、Suspense、KeepAlive、Transition
- 无指令系统（v-show 之外的自定义指令）、无 v-memo、v-once 只有半实现
- props 更新不做"删除已消失的 key"；attrs 透传只处理单根元素
- 双端 diff 的移动用"位置是否正确"近似，没有最长递增子序列（见 03 篇的对比）
- 表达式前缀化用保守的正则近似，没有完整 babel 解析（复杂表达式可能误判）
- 无 TypeScript、无生产模式、无告警分级

对应章节：《Vue.js 设计与实现》第 5～16 章的核心思想都覆盖了，
第 6 篇之后的优化细节做了教学级简化。
