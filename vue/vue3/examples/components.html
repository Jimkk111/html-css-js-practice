组件化原理：没有任何魔法

下面是一个完全跑在 vue-mini 上的待办事项应用。它用到组件化的所有核心机制： props 下行、emit 上行、插槽分发、生命周期。 所有机制都归结为一句话：组件也是 vnode，只不过 type 是对象；渲染器分派到独立的组件流程，流程内部又回到"执行 render → 得到子树 vnode → patch"。

应用（跑在你正在看的浏览器里）

组件生命周期日志

试着勾选/删除/新增条目，观察每个组件的挂载与卸载；点「重置列表」看整批卸载的顺序。

这个应用里的组件通信路线

App  持有 todos: reactive([]) 和 todosLeft: computed
 │  模板: <TodoInput @add="addTodo" /> / <TodoItem v-for @toggle @remove />
 │  props 下行 ↓            emit 上行 ↑
 ├─ <TodoInput :placeholder="..." @add="addTodo">
 │     内部维护草稿 ref，回车时 emit('add', 文本)
 ├─ <TodoItem v-for="todo in todos" :todo="todo">
 │     接收 todo prop（浅响应式），勾选/删除时 emit('toggle'/'remove', todo)
 │     勾选框旁的 <slot name="tag"> 展示 App 分发的插槽内容（作用域插槽传回 todo）
 └─ <AppFooter :count="todosLeft">
       props 没变时父组件重渲染会跳过它（shouldUpdateComponent）

底层只发生了三件事：
  ① 父 render 执行 → 创建子组件 vnode（type 是对象 → 渲染器走 processComponent）
  ② mountComponent：创建实例 → initProps → 执行 setup → 渲染 effect → patch 子树
  ③ 子 emit('add', v)：在 vnode.props 里找 onAdd 并调用 → 父的回调改父的状态 → 父重渲染 → 新 props 流向子
