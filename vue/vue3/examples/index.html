vue-mini：跟着《Vue.js 设计与实现》手写一个最小可用 Vue 3

零依赖、纯 ESM。这个项目回答一个核心问题：模板字符串是如何一步步变成真实 DOM， 并且在数据变化时只更新必要部分的？ 下面的四个演示页面对应它的四大模块，边玩边对照源码和 docs/ 里的长文讲解。

四条主线，一条闭环

用户写模板
   │  "<button @click="count++">{{ count }}</button>"
   ▼
① 编译器 compiler-core     tokenize → parse → transform → generate
   │  产出 render 函数（含 patchFlag、静态提升、Block Tree 等优化）
   ▼
② 渲染器 runtime-core      render 函数执行 → VNode 树 → patch(old, new) → 最小化 DOM 操作
   │            ▲
   │            │  数据变化时重新执行 render，只 diff 差异
   ▼            │
③ 响应式 reactivity        Proxy 拦截读写 → track 收集依赖 → trigger 通知 effect → 调度器批量更新
   │
   ▼
④ 组件系统 runtime-core    setup / props / emit / slots / 生命周期
      组件也是一个 vnode（type 是对象），渲染流程与元素共用同一套 diff

怎么运行

cd vue/vue3
node server.mjs        # 打开 http://localhost:5173/
npm test               # 114 个单元测试（跑在自制的 mini-dom 上，无需浏览器）

目录导读

vue/vue3
├── src/
│   ├── shared/            位标记（ShapeFlags/PatchFlags）、工具函数、class/style 归一化
│   ├── reactivity/        effect、reactive、ref、computed、调度器（批量更新队列）
│   ├── runtime-core/      vnode、渲染器（mount/patch/双端diff）、组件系统、h、生命周期
│   ├── runtime-dom/       nodeOps（真实 DOM 操作）、patchProp（属性/事件/样式）、createApp
│   ├── compiler-core/     tokenize（状态机）→ parse（栈）→ transform（优化）→ codegen
│   └── index.js           对外出口：把编译器注入运行时（"完整版"的关键）
├── examples/              四个可视化演示页面（就是本站的四个 tab）
├── docs/                  每个模块一篇长文讲解（强烈建议对照阅读）
└── tests/                 mini-dom + node --test，覆盖编译器/渲染器/响应式/组件全链路

建议的学习顺序

① 先打开「响应式系统」理解数据怎么驱动函数； ② 再看「编译流水线」理解模板怎么变成 render 函数； ③ 然后是「渲染器与 Diff」理解 vnode 怎么变成 DOM 并最小化更新； ④ 最后「组件化原理」把三者串成闭环 —— 你会发现组件没有任何魔法， 它只是"type 为对象的 vnode"。
