渲染器：VNode 树 → 真实 DOM，且只做「必要」的 DOM 操作

下面的列表由渲染器驱动。点击按钮改变数据，右侧日志是渲染器真实的操作记录 （由包装 nodeOps 获得，不是模拟）。重点观察：带 key 的列表在乱序时不重建 DOM，只移动； 文本更新只走 setText，连元素都不碰。

    这条链路里发生了什么

    数据变化（比如 list 被替换）
   ↓  响应式系统 trigger
组件的渲染 effect 重新执行 render 函数 → 得到新 VNode 树
   ↓
patch(oldVNode, newVNode)          ← 上一次的 VNode 存在 container._vnode 上
   ├─ 类型/key 相同 → 复用 DOM（el 指针直接继承）
   │    ├─ patchProps：只改变化的属性（编译产物还带 dynamicProps 清单，跳过静态属性）
   │    └─ patchChildren → patchKeyedChildren
   │         ① 头-头 扫描（能复用就跳过）  ② 尾-尾 扫描
   │         ③ 新的有剩 → 挂载新增          ④ 旧的有剩 → 卸载多余
   │         ⑤ 中间乱序区 → 按 key 建 Map，判断是否需要移动，从后往前插入
   └─ 不同 → 卸载旧的，挂载新的（唯一会"重建"的情况）
